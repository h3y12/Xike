2026-09-24。一份说明，讲清「要的是什么、怎么实现的、怎么用、怎么验证的、还剩什么」。

## 1. 你提的需求原文

> 加入闹钟功能，闹钟有重复/一次性/响铃后删除功能，重复能按每日和每周重复。有提示语。
> 界面显示紧凑，每个闹钟一个方块只显示时间和开关，黑色字闹钟生效，浅灰色字不生效，
> 闹钟按时间排列，以凌晨四点为界。能设置起床闹钟，起床闹钟能设置成防赖床的连锁闹钟：
> 响铃时关闭一个，第二个仍会响起，手动关闭时一起关闭。设置时可以设置起始时间、间隔时间、
> 响铃次数来自动设置多个闹钟，也可以手动设置。

## 2. 你确认过的口径（我按这些做的）

| 项 | 你的选择 |

### 你后来澄清的两条关键语义

**① 「以凌晨四点为界」到底是啥意思**

你的原话：*"把 1 点-3 点的闹钟放到 24 点以后，4 点作为新一天。"*

```
04:00 → 0      （新的一天从这里开始）
05:00 → 60
23:00 → 1140
01:00 → 1260   （接在 23:00 后面）
03:59 → 1439   （这一天里最后一个）
```

所以列表顺序是 `… 22:00 → 23:00 → 01:00 → 02:00 → 03:00`，而且 `04:00` 排在 `03:59` **前面**。

**② 「间隔」和「关掉」的关系**

你的原话：*"例如我设置了3分钟的间隔，8点的闹钟，那么不响是想了半分钟还是1分钟再关掉，
都应该在8:03再次准时响起"*

实现成了：**每个连锁闹钟各自钉在自己的钟点上**。`08:00 + 3分 + 3次` 生成的
`08:00 / 08:03 / 08:06` 三个闹钟互相独立 —— 你 8:00 关掉第一个（哪怕磨蹭到 8:02 才点
「知道了」），第二个**仍在 8:03:00 准时响**，不会漂成 8:05。

三种关闭语义：

- 关掉串里**不是最后一个** → 只记这一响过了，后面的照常响（这就是防赖床）
- 关掉**最后一个** → 这一串结束；整串都是「仅一次」的话整串删掉，重复的只结束这一轮
- **手动关整串** → 剩下的**一起关**（你说的「手动关闭时一起关闭」）

## 3. 被你这个问题逼出来的一个真 bug

`AlarmBook` 里原本写成「**这个闹钟响过一次就从此跳过**」：

```csharp
if (_firedAt.ContainsKey(a.Id)) continue;   // ❌
```

对一次性闹钟看不出来（它本来就要删），但**「每天 8:00」的闹钟第二天再也不会响**。
而如果我只测「今天到点响不响」，这个 bug 全绿过检。

现在改成记**时刻**（`id → 哪一次响铃报过了`），只有「同一个时刻已经报过」才跳过。
两端都补了跨天 / 跨周的回归用例：

```
PASS  第一天 07:00 响了
PASS  第二天 07:00 还得响（每天重复）
PASS  第三天也响
PASS  周一 07:00 响了
PASS  周二 07:00 不响（只勾了周一）
PASS  下周一还响
```

## 4. 电脑版怎么用

- **挂件第 3 块「闹钟」**：临近半小时内有闹钟才出现，平时完全不占位置。
  每个闹钟一个方块，**只显示时间和开关**；生效的近白字、不生效的浅灰字；按四点分界排序。
- **改闹钟**：右键挂件（或托盘图标）→ **「闹钟设置…」**。窗口两个页签：
  - **闹钟**：逐条增删改。填时间 + 名字（可不填）+ 重复方式（仅一次 / 每天 / 每周勾星期几）。
    「仅一次」可勾「响过之后自动删除」。
  - **起床闹钟**：填**起始时间 + 间隔 + 次数**，一键生成一串；也能一个个手动加。
- **响铃时**：屏幕中间的弹窗显示闹钟名、提示语、还有几秒自动安静，两个按钮
  **知道了 / 稍后提醒**（回车 = 知道了，Esc = 稍后提醒）。响 30 秒自动安静，但弹窗留着，
  不处理不会自己消失 —— 防赖床靠的是「下一个按间隔再响」。
- 右键菜单里可以「收起「闹钟」块」。

## 5. 安卓版怎么用

- App 里「闹钟」卡片 = 设置页。方块 = 时间 + 开关，生效近黑、不生效浅灰，按四点分界排序。
- 「加一个闹钟」/「起床闹钟（连锁）」两颗按钮，同电脑版的两种设置方式。
- 临近半小时的闹钟写进常驻通知；到点用高优先级通知响铃，通知上直接有
  **「知道了 / 稍后提醒」**，不必先打开 App。
- 「响铃时震动」可关。

## 8. 已知限制

- **一次性闹钟若一直没被处理**，会留在列表里、第二天同一时刻还会响。
  它「响过」才会被删；一直没响的不算响过。不想留就手动删掉。
- **错过的闹钟不补响**（你选的）。电脑关机、手机被系统杀掉期间错过的，开机后不会补。
- **安卓端闹钟只在悬浮窗服务运行期间才会响**（判点在 `OverlayService` 每秒的 tick 里）。
  在 App 里关掉悬浮窗时会有提示。
- 「稍后提醒」是**新建一个一次性闹钟**，不属于原来的连锁串 —— 免得一条稍后提醒把整串唤醒逻辑带过去。

## 9. 这次踩到的坑（已记进 `docs/PITFALLS.md` §17 与安卓 `README.md`）

本机**删文件慢到病态**（`jstack` 抓到 Gradle 的执行线程 121 秒里烧 86 秒 CPU 在
`DeleteFile0`），所以任何「清空输出目录」的构建步骤都像死锁：MSBuild 的 `CoreClean`、
Gradle 的 `mergeDebugResources` 都会十几分钟没动静。**两边都是慢，不是坏。**

另外踩到两件「构建中途改源码」的事故：
- 改了 `res` 之后 R 类已经生成过 → Kotlin 认得新字符串、R 类里却没有 → 编译失败。
  重跑一次即好，**不是代码问题**。
- 上次被杀掉的构建在 `app/build/intermediates/.../mergeDebugResources` 里留下坏状态，
  导致 `Duplicate resources`。**用「改名挪开」而不是删除**解决了。

还有一条自检「假失败」，和第 16 节同一类：安卓的 `chain_lastOneEndsTheChain` 原本
**直接 dismiss 了从没响过的闹钟**，然后断言后面那段只该报 1 个 —— 产品行为是对的
（没响过的当然还会响），是我这条用例的时序写得不像真的。已改成与电脑版同一种写法
（每次先 `dueBetween` 拿到响铃、再 dismiss、再推进）。

## 10. 快照替我抓出的两个问题（都已修）

我在收尾时把「闹钟设置窗」和「响铃弹窗」也画进了对照图 `_verify\闹钟界面.png`，
一出图就发现两处对不上：

**① 一张卡的标注说了它画不出来的东西（假证据）**

原来那张卡标着「闹钟块：生效亮字、不生效浅灰字」，图上却只有一个闹钟。
原因是**挂件里的闹钟块只收「生效且半小时内会响」的闹钟** ——
我摆的那个"不生效"的（06:30 起床）和一个"周二不响"的每周闹钟，本来就进不了这一块，
灰色永远画不出来。

而你要求的「**黑色字闹钟生效、浅灰色字不生效**」这个观感，真正存在的地方是
**闹钟设置窗的列表**（挂件块里只有"会响的"，压根没有灰色这回事）。
所以改法是：给对照图补上闹钟设置窗的两页 + 响铃弹窗，卡片标注改成如实描述。
现在 `闹钟界面.png` 里那张面板能直接看到 04:10（亮）→ **06:30（明显浅灰、按钮写「已关」）**
→ 08:00（亮）→ 23:50（亮）→ 01:30（亮）—— 顺带也把「以凌晨四点为界」的排序摆在眼前了。

> **更正说明**：这张卡在 09-24 之前的版本里标的都是"生效亮字、不生效浅灰字"，
> 属于标注与事实不符，现予撤销。

**② 打开闹钟设置窗时，标题下面那行说明是空的**

`AlarmWindow.xaml` 里页签写的是 `TabNormal IsChecked="True"`，这会在
`InitializeComponent` 期间就触发 `Checked` 事件，而那时另一个页签的控件还没建好 ——
事件处理函数第一句就把这次触发 `return` 掉了（防的是空引用）。代价是：
**首屏那行说明（"每个闹钟一个方块，按时间先后排列（以凌晨四点为界）。"）是空的，
点一下页签才冒出来。** 不抛异常、不崩溃、自检也全绿，只有看图才发现。

顺带查出同一处的连带问题：普通页报错是**顶在说明行上**显示的，
但清错时只还了颜色、没还文字 —— 于是说明行会一直挂着刚才那句错话。

改法：把"页签落实下去"抽成 `ApplyTab()`，构造函数和页签事件都调它；
清错时把说明文字也写回去。并补了 9 条自检钉住它（`### 闹钟设置窗的说明行`），
其中两条专门盯**窗口宽度只能有一个来源**——这个漂移同样光看图看不出来，
因为离屏渲染（`Snapshot.TakePanel`）会把宽度强行设成 `CardWidth`，
XAML 里就算偷偷写死一个别的数字，图照样是对的，只能直接读窗口属性。

## 11. 还剩一步（需要你动手）

`dist\TimeGuard.exe` **已经是新版**（561,817 字节），
但你桌面上正跑着的挂件还是旧进程（PID 12528）—— 它是从
`dist\TimeGuard.exe.old-20260923` 那份起的（上次换版时把旧文件改了名，进程就跟着锁在那个文件上）。
