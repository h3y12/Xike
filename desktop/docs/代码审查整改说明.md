## 二、逐项说明

### P1-1 签名私钥与明文口令放在同一目录（安卓）

**原来**：口令硬编码在 `app/build.gradle.kts` 里，而 `keystore/timeguard.jks` 就在同级目录。
拿到仓库的人可以直接给 App 签一个「看起来是官方」的更新包。

**现在**：口令外置为两级取值，代码里不再出现任何明文：

```kotlin
fun secret(envName: String, propName: String): String? =
    System.getenv(envName)?.takeIf { it.isNotBlank() }        // ① 环境变量优先
        ?: keystoreProps.getProperty(propName)?.takeIf { it.isNotBlank() }  // ② keystore.properties
```

- 新增 `keystore.properties`（**已进 `.gitignore`**），装口令
- 新增 `.gitignore`，排除 `keystore.properties` / `keystore/` / `*.jks` / `local.properties` / `build/` 等
- 没配口令时 `release` 不挂签名配置，Gradle 打中文提示而不是报错

**验证**：`gradle :app:signingReport` 显示签名指纹
`SHA-256: 3C:7E:B7:FC:…:B0:3B`，**与改前完全一致** —— 已安装的版本仍能用新包覆盖更新。

> 换机器时只要把 `keystore/` 和 `keystore.properties` 一起带走，签名指纹就不变；
> 少了这两个文件就只能卸载重装。README 里已写明。

### P1-2 负数输入未处理（桌面）

**原来**：`Countdown.TryParse` 的钟点分支写的是 `if (n <= 23)`，负数顺着这条边走。
`int.TryParse` 认得 `-1`、`-2147483648`，而 `new TimeSpan(n, 0, 0)` 的小时参数只允许 ±23 ——
`-24` 不抛异常却得到 `-1.00:00:00`（截止点跑到昨天），`int.MinValue` 直接抛 `ArgumentOutOfRangeException` 崩程序。

**现在**：钟点分支补了负数下界，明确拒绝并给中文提示。

### P2-3 校验失败仍保存（安卓）

**原来**：`persistRules()` 走的是宽松解析，非法输入会被静默修正后照样存盘，
用户以为改成功了，实际存进去的是别的东西。

**现在**：新增 `validatedRules()` —— 严格按控件原文判断，分钟/分数 `toIntOrNull()` 失败即拦、
三个时刻 `tryParseHm` 失败即拦，最后再过一遍 `SleepRules.validate()`。
不合法就写「⚠ …（未保存）」并**直接返回，不落盘**。
`rules()` 保留宽松口径只用于界面预览（加了注释警示）。

### P2-4 配置直接覆盖写 + 吞异常（桌面）

**原来**：`File.WriteAllText` 直接覆盖。断电/磁盘满时留下空文件或半截 JSON，
窗口位置和整套规则全丢；`catch {}` 还把失败藏起来。

**现在**：写盘改成三步 —— ① 先写完整内容到 `.tmp` ② 备份 `.bak` ③ 原子替换。
读盘时主文件坏就回落 `.bak`，两个都坏才回落默认值并把坏文件改名 `.corrupt` 留证。
写失败**不动原文件**，顺手清理 `.tmp`。

### P2-5 暂停快照丢小数秒（安卓）

**原来**：只存整秒，暂停 45 分钟零 0.5 秒再恢复，会多出 0.5 秒。

**现在**：`CdSnapshot` 加 `pausedNanos` 字段，恢复时 `pausedSeconds * 1e9 + pausedNanos`。
旧快照没有这个字段也能正常读（默认 0），不会因升级而丢状态。

### P2-6 通知去重卡在「正在启动…」（安卓）

**原来**：去重只看文案，而启动通知和真实状态文案可能相同 → 真实状态被吃掉，
通知永远停在「正在启动…」。

**现在**：① 启动通知只在首次 `onStartCommand` 挂一次（`isForeground` 标志）；
② 去重签名带上动作状态（`text|notifyToggle|clickThrough`），且**只在 `notify()` 成功后才更新签名** ——
失败时下次会重试，不会永久卡死。

### P2-7 按虚拟桌面外接矩形夹取（桌面）

**原来**：`Clamp` 把所有屏幕的外接矩形当一整块。两块并排的屏拼出的矩形中间那条缝
**物理上并不存在** —— 窗口会被夹到缝里，跨在两块屏之间、哪块上都摆不正。

**现在**：新增 `WindowPlacement.ClampToNearest` —— 先按「窗口中心离哪块屏中心最近」挑一块显示器，
再在那块屏的工作区内夹取。旧的单屏 `Clamp` 保留为兼容重载。
调用方 `MainWindow.ScreenWorkAreas()` 逐块屏给工作区（主屏排第一，物理像素按 DPI 换算成 DIP），
枚举失败时退化成一块虚拟桌面，行为与改动前一致。

### P3-8 恢复后结束钟点文案不同步（两端）

**原来**：「到 23:00 结束」这行小字是 `Start` 时按**当时**的截止点写死的。
暂停一晚再继续，截止点已经推到第二天，小字还写着旧钟点。

**现在**：`Resume` 里按新的 `_deadline` 重写 label（仅时长模式；钟点模式本就不提供暂停）。

### P3-9 每字符改动触发九次提交（安卓）

**原来**：`saveRules()` 走 9 次 setter，每次都是一次 SharedPreferences 事务。

**现在**：合并成一次 Editor 事务（9 个 `putXxx` 链式 + 单次 `apply()`）。

## 四、过程中修正的两处「测试自身写错」

这两条一开始报 FAIL，查下来都是**测试写错、产品没问题**，已修正期望值并记进 `docs/PITFALLS.md` §16：

1. **被测分支根本没执行**：`AppConfig.Load()` 有自检隔离短路（直接读隔离文件、不做恢复动作），
   我的新用例正是在隔离模式下跑，那两条分支一次都没走到。
   解法：加 `ExerciseRecoveryForTest` 开关，只在检查这两条时短暂置真。
2. **前置状态被上一个用例改掉**：用例⑤（主文件坏、`.bak` 好）跑完不会隔离文件，
   而用例⑥需要「两个都读不出」才会隔离 → `.corrupt` 永不出现。
   解法：⑥ 里显式删掉 `.bak` 再 `Load()`。

另外修正：`.bak` 里装的是**上一次** `Save` 的内容（不是最新值），期望值应为 `100/200`；
`-0` 在 `int.TryParse` 里等于 `0`（int 没有负零），期望值应为「合法」。
